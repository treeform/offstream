Starx CSS

This page is both the showcase and the usage guide for starx.css, a sci-fi document theme. Copy the CSS file next to any plain HTML document, link it in the head, and write normal semantic tags: h1, p, figure, form, and table. The theme uses a black field, white type, thin rules, corner marks, and a single orange highlight.

The palette is strict. Background is #000000. Text is #f0f0f0. The only accent is #d46837. Headings use Microgramma. Body copy uses Scout. Numbers, codes, and tables use IBM Plex Mono. Do not use aside margin notes in this theme. 

<link rel="stylesheet" href="starx.css">

<main>
  <h1>AXIOM-66</h1>
  <p>Plain prose with <b>strong data</b> and a note.</p>
</main>

Headings

Headings are extended, uppercase, and explicit. They should introduce real structure rather than decorate the page. Optional data-ref on a section prints a small mono label above the content, like a schematic callout.

Third Level Heading

A third level heading works well for sections inside results, methods, or examples. Keep the casing technical and the spacing generous.

Fourth Level Heading

A fourth level heading is small enough for local notes, subsections, and table commentary.

Paragraphs

The style is designed for technical writing. A paragraph can carry narrative, a number, and a source note without changing gears. Use bold for hard facts, italic for soft emphasis, and mark only when a single value must read as the active signal.

A paragraph may also contain a star note*. Put the explanation in the footer. This keeps the reading path clean while preserving provenance and caveats.

SYS 04-AC RELAY 1138.040 / BFR 00039 / AMB 14.85 / NODE 7 REPORTS NOMINAL SIGNAL DRIFT WITHIN ACCEPTED RANGE.

Keep the field black, the type white, and the orange rare enough that every highlight still means something.

Figures

Use ordinary figure and figcaption tags for charts. The CSS does not impose a chart library. Agents can paste in SVG, canvas, or an image produced by another tool. Draw charts on black with white rules and one orange focus point.

Tables

Tables use IBM Plex Mono. Text columns stay left, numeric columns align right, and rules stay thin. Hovering a row shifts its type to orange so the active scan line is obvious.

Item Lists

Item lists can still be ordinary tables. Use the first column for row selection, keep account details in plain cells, and reserve compact controls for row actions.

Agent Notes

Use tags first.
Prefer main, section, p, figure, form, and table before inventing component classes. Skip aside.
Keep orange rare.
Use mark, .highlight, .status, submit buttons, and one chart focus point. Never flood the page with accent color.
Use classes only for intent.
Helpers include .wide, .quiet, .mono, .meta, .status, and .highlight.
Keep the page sparse.
Avoid cards, gradients, heavy borders, and decorative panels. Thin white lines, corner plus marks, and mono labels do enough.
  • Black field, white type, one orange signal.
  • Microgramma for headings, Scout for prose.
  • IBM Plex Mono for numbers and codes.
  • Hairline frames and registration marks.

Notes
